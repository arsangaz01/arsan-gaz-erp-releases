# Agent orchestration status

## Locally verified behavior

* AgentWatcher persists queue items with stable task IDs and processes one queue item at a time.
* The queue tab has a confirmed clear action that pauses dispatch and deletes every JSON queue record, including archived, approval-review, completed, failed, and cancelled records. It preserves task records with a start timestamp, the currently active task, and non-JSON runtime files. Clearing also records the daily-review schedule date so an enabled review is not immediately requeued on the same day.
* Queue residence and Copilot report waits have no expiration. The 20-minute workflow attempt limit applies only after dispatch starts; it is not a queue-wait limit.
* Authorized Telegram updates use `telegram-<update-id>` task IDs. Queued Telegram tasks are selected before ordinary scheduled or local work, without changing the model-priority setting. Telegram tasks retain numeric update order.
* Priority changes apply only when the next queue item is selected. They do not interrupt an active Copilot request, cancel VS Code, or claim to pause a running agent.
* Copilot bridge requests have a separate request ID and carry the AgentWatcher task ID. Completion envelopes preserve both IDs; AgentWatcher rejects a completion whose request ID or job ID does not match. Bridge source version `0.2.17` requires protocol `2` and reports unresolved delivery state in its heartbeat. The extension package was not installed or live-tested.
* An interrupted ordinary task recovered in `Çalışıyor` state is treated as an uncertain result, pauses dispatch, and is never blindly retried. Interrupted Gözcü/Ar-Ge recommendation workflows are also quarantined without replay, but do not pause unrelated queue work. Gözcü cycles persist `Çalışıyor` while their bounded analysis is active and resume only an unfinished analysis step after the persisted backoff.
* Local synthetic test automation is opt-in and bounded. Its default state remains disabled; the test suite exercises its stop and execution caps.

## Locally implemented workflow

* Telegram `/emir` (and plain-text requests routed to VS Code) now persists a `WorkflowJob` in the existing queue item. It retains task/source identity, original request evidence, scope, reviewer, criteria, attempt cap and per-attempt request ID. The request ID is persisted before dispatch and reused as the VS Code bridge request ID.
* `/saglik-gorev [kontrol-adı]` reads the latest local `Supervisor/latest-health.json` report and creates an approval-waiting job only for an actually unhealthy check. Raw health details are intentionally excluded from the VS Code context. This is an explicit Telegram command, not a new poller.
* Completed daily Ar-Ge research and successful Gözcü cycles create a proposal only when the report ends with the exact `ACTIONABLE: yes` marker and its captured material contains a public HTTP(S) citation. Missing, invalid, and `ACTIONABLE: no` decisions remain local. With the default-on automatic forwarding setting, at most six recommendations per local day are queued for Copilot; the count is persisted and retained queue records prevent a restart from resetting the limit. Turning automatic forwarding off restores per-item `/workflow-onay <iş-id>` approval. Automatic forwarding does not claim user approval, accept workflow criteria, or bypass VS Code tool confirmations. Query strings and URL fragments are stripped before citations are stored. Internet text is marked as untrusted data.
* `/workflows` lists pending records associated with the configured authorized chat; `/incele <iş-id>` displays the correlated criterion IDs/text so a user can submit a complete evidence-based review. Ar-Ge proposals never inherit prior Telegram conversation context.
* The bridge completion is accepted only after the existing `Id == requestId`, `TaskId == queue task ID`, `Status == completed`, and non-empty report checks. It is passed through the production `WorkflowOrchestrator.RecordBridgeCompletion` path and saved as `AwaitingReview`; a terminal Copilot event/report is not acceptance evidence.
* `/incele <iş-id> <criterion-id>=met|partial|not-met|blocked:<kanıt>;...` requires one result with evidence for every criterion and the same Telegram chat stored on that item. Only an authorized human review can mark criteria `met` via this command. Independent `TestRun` proofs remain a separate supported path in the orchestrator. Missing/blocked evidence does not complete the job.
* An approval-waiting candidate requires one authorized `/workflow-onay`, which binds approval to a hash of the source evidence/request, scope, reviewer, approval requirement, attempt cap, and all criterion fields (including validator and target). After a failed review, rework is queued under that same approval only when the complete contract hash still matches; changes to command/source, scope, permissions, criteria, reviewer, validator/target, or cap fail validation and require a new candidate/approval. Rework preserves the task ID, increments the attempt, and uses a fresh request ID. Attempts are capped at three (producers may choose a lower cap); each attempt is capped at 20 minutes. Timeouts, interrupted dispatches, uncorrelated/conflicting replay, unsupported state, and approval gaps fail-stop; no active VS Code command is killed or falsely paused.
* Workflow queue state uses atomic temporary-file replacement and `.task`/`.review`/`.done` transitions. Review, rework, blocked, and completed progress stages share the existing durable Telegram outbox and attempt-specific idempotency key. Notification remains default-off, uses only the task's existing authorized Telegram chat, and is not delivered by this implementation run.
* Queue processing remains serial. A new authorized Telegram task is selected before scheduled/local tasks at the next existing queue boundary; there is no fabricated pause/resume API and no dispatch while a workflow is waiting for review/approval.
* Stale uncertain Copilot deliveries are quarantined after 30 minutes without replay, with an `uncertain_stale` failed acknowledgment; the bridge then allows unrelated requests to continue. Younger unresolved deliveries remain blocked. Bridge heartbeat `dispatchBlocked` makes this state visible to AgentWatcher, which waits rather than treating a temporary block as a protocol mismatch.
* Settled root `assistant.turn_end` may establish session readiness after a root assistant message with no pending tool requests, whether or not the message carries a `final_answer` phase. The three-second settle interval and readiness reset on new activity remain in force.
* A queued legacy VS Code task without a workflow contract is upgraded only when its stable ID is an authorized Telegram task; other legacy VS Code tasks fail closed instead of bypassing the new acceptance gate. An interrupted `Çalışıyor` task remains uncertain and is never migrated/replayed.
